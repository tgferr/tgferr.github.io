PROJECT BRAIN Framework

Enterprise Brain Framework — Sistema Operacional Single-File para orquestrar agentes de IA em qualquer repositório

O que é o PROJECT BRAIN?

Um arquivo único (PROJECT-BRAIN.md) que atua como fonte única de verdade, memória viva e orquestrador de desenvolvimento. Copie-o para qualquer projeto e ative o fluxo OpenSpec de demandas com governança rígida antes de qualquer linha de código.

Modos de Operação

Perfil Enterprise Luizalabs

Acionado via MIA + Claude Code CLI: sinergia com o ecossistema corporativo — Context-Mode nativo, RTK no PATH, LSPs automáticos (Go/Python/TS), autenticação Google PKCE e plugins curados.

Perfil Community / Doméstico

Roda em qualquer LLM (Copilot, Ollama, OpenAI) com agentes autônomos puros, formulários interativos via UI e governança local simulada — sem depender de proxy corporativo.

Diretivas Rígidas de Segurança

Nunca commit ou push automáticos

Proibido executar git commit, git push, git merge ou rebase sem instrução expressa e intencional do desenvolvedor. Operações git são somente de leitura ou staging cirúrgico pré-aprovado.

Trava pré-código inegociável

Proibido criar ou editar arquivos sem um plano aprovado em turno explícito. O fluxo obrigatório: Coleta de Requisitos → Explore → Plano → Aprovação [A] → somente então, código.

Transparência do runtime

O agente reconhece o perfil de execução ativo (LiteLLM interno ou LLM da IDE) e adapta comportamento: foco em lógica de negócio, Clean Architecture e testes no CLI; UI nativa no VS Code.

Gateway interativo de abertura

Toda demanda inicia com um gateway de confirmação: menu limpo e atalhos no Claude Code CLI, ou botões clicáveis via vscode_askQuestions no VS Code.

Zero dump de conteúdo bruto

Proibido colar logs, stack traces ou arquivos volumosos na conversa. Processar no sandbox e devolver apenas métricas, causas raiz e diffs mínimos.

Política de retorno enxuto

Respostas sem preâmbulo social. Alterações exibidas apenas como deltas — ## ADDED, ## MODIFIED e ## REMOVED — limitando o contexto a 3 linhas de vizinhança.

Matriz de Personas Especialistas

Antes de alterar qualquer linha, o framework ativa o Deep-Search-Learning e posiciona lentes especializadas na revisão pré-código e no suporte operacional.

Especialista MIA & Tooling

  • Gestão de plugins, skills e MCPs
  • Gateways LiteLLM e certificados SSL

Arquiteto de Contratos

  • Schemas GraphQL, OpenAPI, Protobuf
  • Compatibilidade semântica e @key/@shareable

Engenheiro de Integração

  • Clientes HTTP, pooling e latência
  • Timeout estrito e retry controlado

Compatibilidade

  • Web, mobile e apps legados
  • Coexistência dual (Strangler Fig)

SRE & Observabilidade

  • Latência p95/p99 e traces distribuídos
  • Sanitização de logs — proibido PII

QA & Qualidade

  • Testes de unidade e integração
  • Cobertura 100% de branches e linhas

Ciclo Operacional de Demandas (OpenSpec)

/start-demand — Coleta e Plano

Detecta o perfil de execução, dispara o Explore e apresenta o plano no terminal com parada obrigatória até a aprovação [A] Aprovar plano.

/review-personas — Análise Multi-Ângulo

Debate técnico das lentes especializadas (Arquitetura, Integração, Compatibilidade, SRE e QA). Risco alto ou breaking change? Para e pergunta ao dev.

/execute — Implementação Cirúrgica

Execução baseada em deltas, respeitando Clean Architecture, com suíte de testes de 100% de cobertura. Em falha: diagnóstico conciso, nunca retry cego em loop.

/feed-brain & /close-demand — Destilação

Persiste lições aprendidas na Base Viva (Seção 8), gera o template de entrega MR_DESCRIPTION.md, arquiva artefatos efêmeros e confirma próximos passos.

Regras de Ouro Técnicas

Clean Architecture nos Mappers

Conversões de DTO externo vivem em domain/mappers/, como funções puras, idempotentes e com 100% de testes para cada chave opcional.

Orçamento de Latência & Fallback

Nenhuma chamada upstream pode travar além do SLA (≤ 500ms). Falhas acionam fallback gracioso — null ou payload degradado — sem derrubar a aplicação.

Injeção de Dependência Dinâmica

Nunca singletons estáticos globais que impeçam rebind/mock em testes. Dependências são injetadas sempre que exigem isolamento testável.

Zero Segredo ou PII em Logs

Tokens e senhas nunca em URL params — apenas no body. Proibido logar dados pessoais de clientes nos logs da aplicação.

Nomes ASCII Kebab-Case

Arquivos sem acentos, cedilhas ou caracteres especiais para evitar quebras em runners de CI e no SonarScanner.

Cobertura Inegociável

Testes unitários garantem 100% de cobertura em statements, branches e linhas — com casos explícitos para chaves ausentes, nulos e fallbacks.

Base Viva de Lições Aprendidas

Seção cumulativa e imutável: cada demanda concluída destila suas lições em regras acionáveis, alimentadas pelo /feed-brain.

Setup & Runtime

  • Ferramental gerido unicamente pelo MIA CLI (skills-tk descontinuado)
  • Certificado Netskope exportado para automações de navegador
  • Logins institucionais exigem navegador real e MFA — aguardar confirmação

Arquitetura & Contratos

  • Strategia Strangler Fig em subgrafos legados
  • Metadados abertos com custom scalars e validação de AST
  • Normalização numérica segura com fallback para 0

Integração & Resiliência

  • Zero console.log/print em produção — loggers estruturados assíncronos
  • Headers de experimento/tenant propagados deterministicamente
  • Timeout estrito em toda chamada upstream

Testes & Qualidade

  • Cobertura absoluta de casos de borda (chaves ausentes, arrays vazios, nulos)
  • Fallbacks com exceções explícitas de teste na suíte
  • Testes nunca acoplados a estado global

Como Usar

Instalação rápida

Copie o arquivo ENTERPRISE_PROJECT_FRAMEWORK.md (Enterprise) ou DOMESTICUSER_PROJECT_FRAMEWORK.md (Community) para a raiz do seu repositório como PROJECT-BRAIN.md ou .openspec/brain.md e acione o fluxo com o comando do seu runtime.

Claude Code CLI (Enterprise Luizalabs):

iniciar demanda <CODIGO_CARD_OU_NOME> seguindo @PROJECT-BRAIN.md
# ou
/start-demand <CODIGO_CARD_OU_NOME>

VS Code Copilot Chat (Community / Doméstico):

@PROJECT-BRAIN.md iniciar

O Brain analisa a demanda, dispara a varredura das personas e exibe um plano enxuto no terminal/chat. Parada obrigatória: o agente aguarda sim, aprovo ou ajustes antes de editar qualquer arquivo.
